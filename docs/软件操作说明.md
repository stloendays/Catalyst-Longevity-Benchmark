# Catalyst Longevity Benchmark 软件操作说明

## 1. 软件名称

**Catalyst Longevity Benchmark｜催化剂寿命与长期排序分析系统**

## 2. 软件用途

本软件用于处理异相催化剂的 time-on-stream（TOS）性能轨迹，在不虚构缺失数据、不把稀疏观测强行解释为精确失活时间的前提下，完成：

- TOS 数据导入与完整性校验；
- 催化剂性能归一化；
- `t95`、`t90`、`t80` 阈值寿命判定；
- exact / interval / right-censored / left-censored 语义区分；
- 瞬时性能排序与 pairwise ranking crossover 检查；
- uncertainty-aware ranking reversal 检查；
- 累计性能 AUC 计算；
- JSON 机器可读报告和 Markdown 人类可读报告输出；
- provenance、source-observed、digitized、model-derived 等证据类别保留。

当前科研应用范围聚焦 Ni/Al2O3-based dry reforming of methane（DRM），但软件分析层本身按通用 TOS trajectory 设计。

## 3. 软件结构

```text
输入 CSV
  ↓
数据读取与字段校验
  ↓
按 catalyst_id 组织 TOS trajectory
  ↓
性能归一化
  ↓
阈值寿命与删失状态判定
  ↓
瞬时排序 / pairwise crossover
  ↓
不确定性区间排序审计
  ↓
累计 AUC sensitivity
  ↓
JSON + Markdown 分析报告
```

主要代码模块：

- `src/catlongevity/io.py`：数据读取、字段验证、trajectory 分组；
- `src/catlongevity/endpoints.py`：censor-aware threshold lifetime；
- `src/catlongevity/ranking.py`：ranking、crossover、AUC 与 uncertainty-aware ranking；
- `src/catlongevity/analysis.py`：端到端分析编排；
- `src/catlongevity/reporting.py`：可审计 Markdown 报告生成；
- `src/catlongevity/cli.py`：命令行入口；
- `tests/`：核心逻辑单元测试。

## 4. 输入文件格式

输入采用 UTF-8 CSV。

### 4.1 必填字段

| 字段 | 含义 |
|---|---|
| `catalyst_id` | 催化剂唯一标识 |
| `time_h` | time on stream，单位 h |
| `performance` | 对应时刻的性能值，例如 CH4 conversion 或 TOF |

### 4.2 可选字段

| 字段 | 含义 |
|---|---|
| `paper_id` | 来源论文标识 |
| `metric` | 性能指标名称 |
| `provenance_class` | 数据来源类别，例如 source_observed / digitized / synthetic_demo |
| `lower` | 性能不确定性下界 |
| `upper` | 性能不确定性上界 |

### 4.3 数据约束

- 同一个 `catalyst_id` 的 `time_h` 必须严格递增；
- 不允许重复时间点；
- `time_h` 不得为负数；
- 若提供不确定性区间，则 `lower <= performance <= upper`；
- `lower` 与 `upper` 必须同时提供；
- 软件不会自动补全缺失时间点；
- 软件不会自动生成未观测性能值。

示例文件见：

`examples/example_tos_input.csv`

该文件仅用于演示软件流程，所有记录均明确标记为 `synthetic_demo`，不得作为科研证据使用。

## 5. 运行方法

在仓库根目录运行：

```bash
python -m src.catlongevity.cli examples/example_tos_input.csv
```

默认输出：

```text
catlongevity_report.json
catlongevity_report.md
```

也可以指定输出位置：

```bash
python -m src.catlongevity.cli input.csv -o reports/analysis.json --markdown reports/analysis.md
```

## 6. 阈值寿命判定

对每条 trajectory，以第一个观测值作为归一化基准：

```text
normalized_activity(t) = performance(t) / performance(first observation)
```

软件计算：

- `t95`：normalized activity 首次达到或低于 0.95；
- `t90`：首次达到或低于 0.90；
- `t80`：首次达到或低于 0.80。

### 6.1 状态语义

**exact**  
仅用于来源明确报告了精确 threshold time 的情况；不能由离散采样点自动推断。

**interval**  
已知 crossing 位于相邻两个 source-supported observation time 之间。

**right_censored**  
实验结束时仍未观察到 threshold crossing，只能说明寿命大于最后观察时间。

**left_censored**  
首次观察时已经达到或低于 threshold，因此 crossing 发生在首次观测之前，但具体时间未知。

## 7. 排序与 crossover

### 7.1 Instantaneous ranking

瞬时排序用于比较相同 operation horizon 下各催化剂当前性能。

Pairwise crossover 只有在两个催化剂存在至少两个共同 source-supported observation time，并且相对排序发生符号变化时，才返回 interval-supported crossover bracket。

软件不会因为一条平滑拟合曲线发生相交，就把该相交点改写为 source-observed crossing time。

### 7.2 Uncertainty-aware ranking

当两个催化剂在共同时间点均具有 `[lower, upper]` 不确定性区间时：

- A 只有在 `A.lower > B.upper` 时才被证明优于 B；
- B 只有在 `B.lower > A.upper` 时才被证明优于 A；
- 区间重叠时视为 ambiguous；
- ambiguous observation 不能单独创造 ranking reversal claim；
- 若两个相反的 proven ordering 中间存在 ambiguous points，crossover bracket 应保持较宽而非人为收窄。

## 8. Cumulative AUC

软件使用相邻观测点之间的梯形积分计算累计性能：

```text
AUC = Σ 0.5 * (y_i + y_{i+1}) * (t_{i+1} - t_i)
```

由于稀疏文献数据之间默认采用 piecewise-linear interpolation，软件始终将该结果标记为：

`derived_piecewise_linear_sensitivity`

除非来源本身提供足够密集或连续记录，否则不得把 AUC 当成 source-observed quantity。

## 9. 输出报告

### 9.1 JSON 报告

JSON 用于后续自动化、Agent、benchmark evaluator 或数据处理管线。

主要字段包括：

- analysis semantics；
- 每个 catalyst 的原始 TOS 序列；
- normalized activity；
- t95 / t90 / t80；
- censoring status；
- cumulative AUC；
- provenance classes；
- pairwise crossover audit；
- uncertainty-aware crossover status。

### 9.2 Markdown 报告

Markdown 用于人工审阅与项目记录，明确显示：

- 每条 trajectory 的观测数量；
- threshold lifetime status；
- pairwise crossover status；
- uncertainty-aware status；
- interpretation boundary。

## 10. 科研证据边界

软件必须遵守以下原则：

1. source-observed、digitized、model-derived quantities 分开保存；
2. qualitative activity-stability tradeoff 不自动计为 numerical ranking inversion；
3. 稀疏数据不推断精确 crossover time；
4. 未跨 threshold 的试验必须保留 censoring；
5. source conflicts 不静默平均；
6. mechanism labels 必须有论文中的 TGA / TEM / XRD / Raman / TPR 或其他明确证据；
7. paper-grouped / leave-one-paper-out 是跨论文模型验证的主要结构；
8. synthetic demo 永远不得进入真实科研结果表。

## 11. 异常与错误处理

软件在以下情况直接停止并返回明确错误，而不是自动修复数据：

- 缺少必填列；
- CSV 无数据；
- 时间点为负；
- 同一 catalyst 出现重复或非递增时间点；
- 不确定性区间不完整；
- `lower > upper`；
- performance 不在声明的不确定性区间内；
- 首个 performance 为 0，导致无法进行归一化。

这种 fail-closed 行为用于避免数据问题被静默带入科研结论。
