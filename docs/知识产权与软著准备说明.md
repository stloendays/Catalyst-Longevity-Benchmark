# 知识产权与软件著作权准备说明

本文件用于明确当前软件在登记材料中的产品边界、功能边界和数据边界，方便后续整理申请材料、操作说明、源代码文档和界面截图。

## 1. 对外软件名称

**软件全称：催化剂长期稳定性评估与实验决策系统**  
**建议简称：催化剂稳定性决策系统**

该名称采用“应用对象 + 核心功能”的结构，直接对应当前已经实现的催化剂长期稳定性数据分析、实验条件检查、寿命计算和实验辅助功能。

工程内部仍可保留 `Catalyst Longevity Research` 等英文标识，用于代码、构建目标和可执行文件管理；对外说明材料和桌面界面应以中文产品名称为主。

## 2. 登记材料中的软件定位

本系统面向高校实验室、科研院所、催化剂研发团队和化工企业研发人员，用于对催化剂长期稳定性实验进行数据整理、质量检查、寿命分析、条件核对、同时间比较和后续实验辅助，并支持论文资料整理、本地项目管理和分析报告输出。

建议在登记材料中重点描述当前原生 Windows 桌面程序已经实现的功能，不把尚处于研究或接口预留状态的外部服务写成软件主体能力。

## 3. 当前软件产品边界

登记材料中的主要软件对象为 C++ / Qt 原生桌面应用，核心流程为：

```text
用户实验数据 / 内置数据集
        ↓
数据检查与条件检查
        ↓
长期性能与寿命分析
        ↓
同时间催化剂比较
        ↓
下一轮实验建议
        ↓
资料整理与人工确认
        ↓
本地项目保存 / PDF 报告
```

上述流程能够独立完成，不依赖浏览器界面，也不要求外部 AI 服务才能运行核心分析功能。

## 4. 已实现的软件模块

### 4.1 项目管理

- 新建项目；
- 打开项目；
- 保存和另存项目；
- `.clrproj` 本地 SQLite 数据持久化；
- 实验数据、资料关联和人工确认状态统一保存。

### 4.2 数据输入

- CSV 数据导入；
- Excel `.xlsx` 数据导入；
- 中文和英文常用列名识别；
- 内置数据集直接载入。

### 4.3 内置数据集

系统原生编译 5 组模拟数据，用于功能演示、培训和流程验证：

- 长期稳定性对比；
- T90 区间定位；
- 长周期寿命下限；
- 实验条件差异检查；
- 数据质量检查。

内置数据与外部导入数据进入同一套分析流程，并明确标记为模拟数据，不作为真实科研实验结论。

### 4.4 数据质量检查

- 重复时间点检查；
- 无效或异常数值检查；
- 实验条件缺失检查；
- 同一催化剂内部条件变化检查；
- 不同催化剂之间的实验条件差异检查；
- 数据完整度评分；
- 问题说明和处理建议。

### 4.5 催化剂寿命分析

- 初始性能；
- 最新性能；
- 性能保持率；
- T95；
- T90；
- T80；
- 左删失、区间和右删失状态保留；
- 长期性能曲线。

系统不把两个实际观测点之间的插值结果冒充为精确实验寿命。

### 4.6 实验条件检查

可检查已提供的：

- 温度；
- GHSV；
- WHSV；
- 压力；
- 进料比。

当不同催化剂的明确实验条件不一致时，系统停止输出直接领先结论。

### 4.7 同时间对比

系统自动寻找两个催化剂最近的共同实际观测时间，计算双方性能差值并给出比较状态。条件不一致时只显示检查信息，不进行直接排名。

### 4.8 实验建议

可根据当前数据自动生成规则化建议，包括：

- 观测点不足时建议补充采样；
- T90 尚未达到时建议延长测试；
- T90 位于两个采样点之间时建议在区间内增加采样；
- 首个观测点已低于阈值时建议提前采样；
- 条件信息不足时建议补全实验记录。

### 4.9 资料整理

- PDF 文本层读取；
- TXT / Markdown / CSV / TSV 资料读取；
- DOI、温度、测试时长、转化率等候选信息识别；
- 资料与催化剂关联；
- 资料与时间点关联；
- 人工确认和取消确认；
- 已确认资料的受控使用范围。

### 4.10 报告输出

系统可生成 PDF 分析报告，包含数据检查、条件检查、寿命结果、同时间对比、实验建议以及资料来源信息。

## 5. 软著材料建议重点

材料应围绕一个清晰、可重复的软件使用闭环展开：

1. 新建项目；
2. 选择内置数据集或导入用户实验数据；
3. 查看数据完整度和检查结果；
4. 查看长期性能曲线；
5. 查看 T95 / T90 / T80；
6. 查看实验条件检查；
7. 查看同时间对比；
8. 查看后续实验建议；
9. 整理论文资料并人工确认；
10. 保存项目并导出 PDF 报告。

建议截图时优先使用内置数据集，因为可以稳定触发不同功能状态，便于操作说明与实际软件界面保持一致。

## 6. 软件层与科学思想层的边界

软件著作权材料可以重点体现程序代码、数据结构、界面工作流、分析逻辑的具体软件实现，但不应把通用科学观点或公共知识描述为软件独占内容。

### 软件实现层

可以明确记录：

- 数据读取和字段映射；
- 数据质量检查程序；
- 寿命阈值计算程序；
- 实验条件比较程序；
- 同时间比较程序；
- 实验建议规则程序；
- 本地数据库存储；
- 资料关联和人工确认；
- 图形界面；
- PDF 报告生成。

### 通用科学与数学概念

不应因为写入软件就描述为独占保护内容，例如：

- 催化剂失活和长期稳定性的科学概念；
- T95 / T90 / T80 的一般含义；
- censoring / 删失的统计思想；
- 公共论文或数据库中的事实；
- 他人论文中的实验数据、图表和文字。

## 7. 数据与来源边界

需要持续区分：

- 用户自己的实验数据；
- 用户导入的论文或资料；
- 外部公开信息；
- 系统计算得到的结果；
- 系统内置模拟数据。

系统内置数据必须继续明确标记为“模拟 / 演示 / 流程验证数据”，避免和真实实验结果混淆。

不要直接把他人论文的受版权保护图表、大段文字或受限制数据库内容重新包装为软件自有数据集。

## 8. 安全与权属注意事项

- API Key 不写入公开仓库；

- 若成果涉及学校、导师、公司或资助项目，应按对应知识产权条款核实申请主体；
- 新增第三方依赖时继续保留许可证和第三方声明。
